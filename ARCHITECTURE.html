KungFu Chess — ארכיטקטורה וזרימת נתונים

מדריך פנימי לקוד: היררכיה, אחריות של כל קובץ, והסבר על כל פונקציה.

שחמט בזמן־אמת: מהלכים וקפיצות מתממשים אחרי השהיה, וקפיצה על משבצת יכולה ליירט מהלך יריב נכנס.

Python OpenCV (cv2) Strategy + Command + DI 2 נקודות כניסה: main.py / play.py

מסמך זה נוצר ב־15/07/2026 מתוך קריאת קוד המקור (ללא התמונות). כל התוכן מוטמע — אין תלות באינטרנט.

1. סקירה כללית

הפרויקט הוא גרסת שחמט בזמן־אמת (KungFu Chess): אין תורות — שני השחקנים מזיזים בו־זמנית, וכל מהלך "נוסע" על הלוח לאורך זמן במקום לקפוץ מיידית ליעד. הרעיון המרכזי שמכתיב את כל הארכיטקטורה:

  • הלוח (Board) מחזיק רק תפוסה לוגית — איזה כלי על איזו משבצת. הוא לא יודע כלום על פיקסלים, זמן או אנימציה.
  • התנועה בזמן (RealTimeArbiter) — כלי "בטיסה" חי מחוץ ללוח עד שהוא נוחת. השעון מוזרק (advance_time(dt)) ולא נלקח משעון הקיר, כדי שהכול יהיה דטרמיניסטי וניתן לבדיקה.
  • המנוע (GameEngine) הוא רק מתאם דק — הוא לא מכיל חוקיות שחמט, לא מודל תנועה ולא ניקוד. הוא מזמן משתפי־פעולה שכולם מוזרקים אליו בבנאי (Dependency Injection).
  • שתי נקודות כניסה חולקות את אותו מנוע: מסלול טקסט (main.py, למחברת/גריידר של VPL) ומסלול גרפי בזמן־אמת (play.py).

ארבע הדרישות של המטלה שהארכיטקטורה עונה עליהן: (1) תמיכה בפורמטי לוח נוספים דרך מתאמי טעינה ולא ירושה; (2) אין חוקים קשיחים — כל כלי הוא אסטרטגיה רשומה במרשם; (3) קוד נקי — אחריות אחת לכל מודול, אין קבועי־קסם (הכול ב־config/settings.py); (4) בדיקות + הזרקת תלויות מלאה.

2. שכבות הארכיטקטורה

הזרימה בין השכבות תמיד כלפי מטה — שכבה גבוהה תלויה בנמוכה, אף פעם לא להפך. זה מה שמאפשר לבדוד ולבדוק כל שכבה בנפרד.

Config — config/
כל הקבועים: תזמונים, צבעים, כיוון רגלי, ערכי כלים, פריסת חלון. שום מודול אחר לא מכיל מספרי־קסם.
Model — מודל — board/
Board יחיד (תפוסה לוגית). פורמטי קלט מומרים אליו במתאמים ב־loaders.py.
Movement Rules — חוקי תנועה — rules/
אסטרטגיית תנועה לכל סוג כלי, מרשם (Registry), מנוע אימות קריא־בלבד, וחוקי ניצחון/הכתרה.
Real-time — זמן־אמת — realtime/
כל התנועה על ציר הזמן: מהלכים/קפיצות פעילים, זמני הגעה, לכידה ויירוט. מדווח ArrivalEvent.
Application — מנוע — game/
GameEngine (גבול הפקודות הציבורי), Controller (בחירה + לחיצות), יומן מהלכים, לוח ניקוד, נוטציה.
View — תצוגה — view/
מודלי־קריאה בלתי־ניתנים לשינוי (GameSnapshot לטקסט, RenderModel לגרפיקה) + רינדור טקסט.
Graphics — פרימיטיבים גרפיים — graphics/
המקום היחיד שמכיר את cv2: Img (ציור), Window (חלון+קלט), טעינת ספרייטים.
UI — לולאת המשחק — ui/
GameLoop, רינדור גרפי, HUD, פאנלי מהלכים, תרגום קלט.
Gateway — תפר רשת — gateway/
Protocol שמפריד את ה־UI מהמנוע הקונקרטי, כדי לאפשר מנוע מרוחק בעתיד.

4. זרימת נתונים

4א. מסלול הטקסט (main.py) — עבור הגריידר של VPL

קלט טקסטואלי (מקטע Board: ומקטע Commands:) → פירוק → טעינת לוח → הרצת פקודות → הדפסת מצב.

stdin ──▶ main.run(lines) │ ├─ parse_input() split into board_lines + commands ├─ build_registry(config) the shared piece-rule registry ├─ load_text_board() text rows ──▶ Board (BoardParseError on bad input) ├─ build_game() wire GameEngine + Controller (composition root) │ └─ for each command ──▶ _dispatch: click x y ─▶ controller.click(x,y) select / request_move jump x y ─▶ controller.jump(x,y) request_jump wait ms ─▶ engine.wait(ms) advance the simulated clock print ─▶ engine.render(BoardRenderer) ──▶ text ──▶ stdout

4ב. המסלול הגרפי (play.py) — משחק בזמן־אמת

אותו GameEngine בדיוק, אבל הלוח נטען מ־board.csv, מצויר גרפית דרך Img, ורץ בלולאת פריימים אמיתית.

play.run() (composition root) │ builds: Window, GameEngine+Controller, InputTranslator, │ SpriteLibrary, GraphicsRenderer, Hud, base canvas ▼ GameLoop.run() ── every frame ──▶ tick(dt): ┌──────────────────────────────────────────────────────────────┐ │ 1. engine.wait(dt) advance clock, resolve arrivals │ │ 2. model = engine.render_model() immutable RenderModel │ │ 3. GraphicsRenderer.render(model, base, selected, targets) │ │ └─ pieces, selection highlight, move hints, rest veil │ │ 4. Hud.draw(canvas, model) title, scores, coords, move panels │ │ 5. window.show(canvas) present via cv2 │ │ 6. window.poll_events() ──▶ InputTranslator.handle(event) │ │ left = click (select/move) · double = jump · quit=stop │ └──────────────────────────────────────────────────────────────┘ Mouse (pixels) ─▶ InputTranslator ─▶ Controller ─▶ BoardMapper (pixel→cell) │ ▼ GameEngine ─▶ RuleEngine (is it legal?) │ RealTimeArbiter (start motion) ▼ on arrival: ArrivalEvent ─▶ engine._apply_events: record move (MoveLog) · award capture (Scoreboard) · WinCondition decides game_over
העיקרון החשוב לזכור: ה־UI אף פעם לא נוגע ב־Board החי או ב־RealTimeArbiter ישירות. הוא מקבל מודל־קריאה בלתי־ניתן לשינוי (RenderModel) ומצייר אותו. זה בדיוק מה ששרת רשת היה מסריאליזציה ושולח ללקוח דק — ולכן gateway.py כבר מגדיר את התפר.

מעבר קובץ־קובץ: נקודות כניסה + config

main.py

תפקיד: נקודת הכניסה של מסלול הטקסט — קורא סקריפט פקודות ומריץ אותו. זה המסלול שהגריידר של VPL מפעיל.

  • run(input_lines, config=settings) — מפרק את הקלט ל־board/commands, בונה registry, טוען לוח (מטפל ב־BoardParseError ומדפיס ERROR), בונה מנוע+controller, ומריץ כל פקודה. config מוזרק כדי שבדיקות יוכלו לספק הגדרות חלופיות בלי monkeypatch.
  • _dispatch(command, engine, controller, renderer) — מנתב מחרוזת פקודה אחת: click/jump ל־controller, wait למנוע, print להדפסת הרינדור.
  • main(input_stream=None) — קורא שורות מ־stdin (או מזרם מוזרק לבדיקות), מנקה רווחים ומעביר ל־run.

play.py

תפקיד: נקודת הכניסה הגרפית בזמן־אמת. בונה את אותו GameEngine, אך טוען מ־board.csv, מרנדר דרך Img ומריץ לולאת פריימים. נפרד מ־main בכוונה כדי ש־main יישאר נגיש לגריידר.

  • load_board_background(config) — טוען את board.png בגודל הלוח הלוגי, כ־Img חדש בכל קריאה (כדי שאפשר יהיה לצייר עליו בלי לזהם קנבס משותף).
  • new_base_canvas(config) — קנבס החלון המלא: רקע בהיר עם הלוח מצויר במקומו הממוסגר, ומקום לפאנלים/קואורדינטות/כותרת/ניקוד שה־Hud מצייר מעל בכל פריים.
  • _compose(config) — טוען את הלוח מ־CSV עם registry משותף. זה החלק היחיד שיודע שהלוח מגיע מ־board.csv; שאר החיווט מואצל ל־game.composition.
  • build_engine(config) — בונה רק את המנוע (היכן שאין צורך בטיפול קלט).
  • build_game(config) — מנוע + Controller מחווט, מוכן לקלט. ה־BoardMapper מוסט לפי מקור הלוח הממוסגר, כדי שלחיצות עדיין יפגעו במשבצת הנכונה.
  • run(config) — שורש ההרכבה: בונה ומחווט כל רכיב, ומעביר ל־GameLoop.

board/ — המודל

board/board.py — class Board

תפקיד: הלוח היחיד בזיכרון שכל לוגיקת המשחק עובדת מולו — רשת של אסימוני מחרוזת ('wK', '.'). ייצוג פנימי יחיד; פורמטי קלט אחרים נתמכים ע״י loader ולא ע״י ירושה.

  • __init__(rows, empty_token=".") — מאחסן רשת פרטית (_cells), גובה ורוחב.
  • width / height (properties) — מידות הלוח.
  • in_bounds(row, col) — האם התא בתוך גבולות הלוח.
  • get / set(row, col[, value]) — קריאה/כתיבה של אסימון תא.
  • is_empty(row, col) — האם התא שווה לאסימון הריק.
  • snapshot() — עותק קריא־בלבד של הרשת לרינדור, כדי שאף אחד לא ישנה את הלוח דרך הערך שהוא מקבל.

board/loaders.py

תפקיד: מתאמי טעינה — ממירים פורמט קלט חיצוני ל־Board. זה "התפר" של הדרישה הראשונה: פורמט חדש = loader חדש, בלי לגעת בשום מודול לוגיקה.

  • class BoardParseError(Exception) — נזרק כשקלט לוח שגוי לפורמט שלו.
  • _valid_text_tokens(registry, colors, empty) — האסימונים החוקיים נגזרים מסוגי הכלים הרשומים במרשם (ולא ממחרוזת קשיחה) — כך רישום כלי מותאם הופך אוטומטית לאסימון חוקי.
  • _ctd26_code_to_token(code) — מתרגם קוד תא של CTD26 (KIND+COLOR, למשל "PW") לאסימון פנימי (color+kind, "wP"). התרגום בגבול המתאם בלבד.
  • load_csv_board(rows, registry, config) — מתאם ל־board.csv של CTD26: תאים מופרדים בפסיק, שדה ריק = משבצת ריקה. מאמת שהלוח מלבני וכל אסימון מוכר.
  • load_text_board(rows, registry, config) — מתאם לפורמט הטקסט (מופרד ברווחים). אותו חוזה אימות. זה המסלול של הגריידר.

rules/ — חוקי תנועה

rules/reasons.py — Reason(str, Enum)

תפקיד: קודי־תוצאה יציבים וקריאים־למכונה למהלך מבוקש. מוגדרים פעם אחת ומשומשים ע״י RuleEngine, GameEngine ו־Controller — במקום מחרוזות פזורות.

יורש מ־str (ולא StrEnum) כדי שירוץ גם על הגריידר שלפני Python 3.10, ושכל חבר יישאר שווה למחרוזת שלו. הקודים: OK; רמת־חוק (OUTSIDE_BOARD, EMPTY_SOURCE, FRIENDLY_DESTINATION, ILLEGAL_PIECE_MOVE); רמת־אפליקציה (GAME_OVER, BUSY_SOURCE, MOTION_IN_PROGRESS, BUSY_CELL, EMPTY_CELL, RESTING).

חי במודול נפרד כדי ששכבת rules הנמוכה תוכל לחלוק את אוצר־המילים בלי לייבא כלפי מעלה משכבת game — התלות תמיד זורמת מטה.

rules/movement_strategy.py

תפקיד: מגדיר את הממשק שכל כלל־תנועה מממש (Strategy pattern) ואת ה־context שהוא מקבל.

  • @dataclass MoveContext — עוטף כל מה שאסטרטגיה צריכה כדי לשפוט מהלך: board, color, start, end, target_occupied. אובייקט חסין־שינוי אחד (במקום 5 פרמטרים) — זה מה שמאפשר להוסיף כלים בלי לשנות אתרי־קריאה.
  • class MovementStrategy(ABC).is_legal(dr, dc, context) — חוק התנועה של סוג כלי יחיד. כלי חדש = מימוש הממשק + רישום במרשם, בלי לשנות מנוע או פרסר.

rules/piece_rules.py

תפקיד: מימושי האסטרטגיה לכל ששת סוגי הכלים הסטנדרטיים.

  • _shape_delta(dr, dc) — עזר: מחזיר (abs(dr), abs(dc)).
  • path_is_clear(board, start, end) — עזר משותף לכלים מחליקים: True אם כל משבצת בין ההתחלה לסוף ריקה. משומש ע״י צריח/רץ/מלכה — נכתב פעם אחת (DRY).
  • KingMovement.is_legal — צעד יחיד לכל כיוון (max(|dr|,|dc|)==1).
  • RookMovement.is_legal — ישר בלבד (שורה XOR עמודה) + מסלול פנוי.
  • BishopMovement.is_legal — אלכסון (|dr|==|dc|≠0) + מסלול פנוי.
  • QueenMovement.is_legal — ישר או אלכסון + מסלול פנוי.
  • KnightMovement.is_legal — צורת L (sorted([|dr|,|dc|])==[1,2]).
  • PawnMovement(directions) — כיוון ההתקדמות מוזרק לפי צבע. _home_row נגזר מגובה הלוח (לא קשיח) כך שצעד־כפול עובד בכל גודל לוח. לוכד באלכסון אחד קדימה כשהיעד תפוס.

rules/rule_registry.py

תפקיד: ממפה אות סוג־כלי לאסטרטגיית התנועה שלו. זו נקודת ההרחבה לדרישה השנייה (אין חוקים קשיחים).

  • class UnknownPieceKindError — נזרק כשמבקשים סוג כלי לא רשום.
  • PieceRuleRegistry.register / get / registered_kinds — רישום, שליפה, ורשימת הסוגים הרשומים.
  • build_default_registry(config) — Factory למערך הכלים הסטנדרטי (K,Q,R,B,N,P). נפרד מהמחלקה כדי שאפשר להרכיב מרשמים חלופיים בלי ירושה.

rules/rule_engine.py

תפקיד: שירות אימות קריא־בלבד — האם מהלך חוקי מול הלוח הנוכחי. לעולם לא משנה את הלוח, לא מתחיל תנועה, ולא יודע על game-over. חסר־מצב לגבי הלוח (הלוח מועבר בכל קריאה).

  • @dataclass MoveValidation — תוצאת בדיקה: is_valid + reason (תמיד נוכח).
  • validate_move(board, start, end) — בודק גבולות, מקור לא־ריק, לא־יעד־ידידותי, ואז מריץ את אסטרטגיית הכלי דרך MoveContext. מחזיר Reason יציב.
  • legal_targets(board, start) — כל התאים שהכלי ב־start יכול לזוז אליהם כרגע (לרמזי־המהלך של ה־UI). מריץ את אותו אימות מול כל הלוח, ולכן יורש הכול (לכידות כלולות, ידידותי/חסום מוחרגים). חדש

rules/game_conditions.py

תפקיד: אסטרטגיות ניצחון והכתרה — ניתנות להחלפה עבור וריאנטים מותאמים.

  • WinCondition(ABC).is_game_over(captured_piece) — האם לכידה מסיימת משחק.
  • KingCaptureWinCondition — נגמר כשנלכד מלך (captured[1]=="K").
  • PromotionRule(ABC).promote(piece, row, board_height) — האם/איך כלי משתנה אחרי מהלך.
  • LastRankPromotion(directions,...) — מכתיר רגלי שהגיע לקצה בכיוונו. שורת ההכתרה נגזרת מאותו PAWN_DIRECTION שמניע תנועה — מקור אמת יחיד ל"לאיזה כיוון כל צבע הולך".

realtime/ — זמן־אמת

realtime/models.py

תפקיד: אובייקטי התנועה החיים מחוץ ללוח.

  • @dataclass Move — כלי בטיסה בין שני תאים: piece, start, end, arrival. שייך ל־Arbiter ולא ל־Board.
  • @dataclass Jump — כלי מרחף על תא עד end_time. בזמן הריחוף הוא יכול ליירט מהלך יריב שנוחת על אותו תא.
  • @dataclass MotionView — תצלום קריא־בלבד של Move לשכבת התצוגה: התחלה, יעד, ו־progress (0..1). מאפשר לרנדרר להחליק כלי בלי לגעת ברשימת ה־Move החיה.

realtime/real_time_arbiter.py — class RealTimeArbiter

תפקיד: הבעלים של כל התנועה בזמן־אמת — מהלכים/קפיצות פעילים, השעון המדומה, תזמון הגעה, ופתרון הגעות/יירוטים. הזמן מתקדם רק כש־advance_time נקרא, אף פעם לא משעון הקיר.

  • @dataclass ArrivalEvent — מה שה־Arbiter מדווח כשכלי נוחת: piece (כפי שהונח, כבר מוכתר), origin, destination, captured (או None). ה־Arbiter משנה את הלוח בעצמו אך לא מכריע ניצחון — רק מדווח.
  • __init__(board, promotion_rule, config) — מאתחל שעון=0, רשימות מהלכים/קפיצות פעילים, ומילון צינונים _cooldowns: cell → (rest_state, start, expiry).
  • clock, has_active_motion, is_moving_from, is_jumping_on — שאילתות מצב על התנועה הפעילה.
  • jump_progress(cell) — כמה הכלי הקופץ בתוך הקפיצה (0=המראה, 1=נחיתה) — כדי שהתצוגה תרים אותו בקשת. חדש
  • cooldown_of(cell) — מצב המנוחה של תא (short_rest/long_rest) או None אם חופשי. בודק תפוגה מול השעון.
  • cooldown_progress(cell) — כמה הכלי בתוך הצינון (0→1) — כדי שהתצוגה תרוקן את הצעיף מלמעלה. חדש
  • is_resting(cell) — קיצור ל־cooldown_of is not None.
  • active_motions() / _motion_view(move) — תצוגות קריאות־בלבד של המהלכים בטיסה, כל אחת עם ה־progress שלה לשעון הנוכחי.
  • start_move / start_jump — יוצר Move (עם זמן הגעה מחושב) או Jump (עם end_time).
  • advance_time(dt) — מקדם זמן מדומה ואז קורא ל־resolve.
  • resolve() — מסדר מהלכים שהגיע זמנם (בלי לקדם שעון), פותר קפיצות, וגוזם צינונים שפגו. מחזיר את ה־ArrivalEvents.
  • _arrival_clock / _move_total(start, end) — משך נסיעה = MOVE_DURATION לכל משבצת, מרחק במטריקת Chebyshev.
  • _settle_move(move) — הליבה: אם יש מיירט קופץ ביעד → הכלי הנע נלכד באוויר והקופץ מזוכה (origin==destination). אחרת: מנקה חסימה ידידותית, מחשב לכידה, מכתיר, מזיז על הלוח, ומתחיל long_rest. עודכן
  • _interceptor_of(move) — הקופץ היריב שיושב על יעד המהלך (אם יש) — הוא מיירט ולוכד.
  • _resolve_jumps() — קפיצה שהסתיימה מתיישבת ל־short_rest על תאה.
  • _begin_cooldown / _prune_cooldowns — מתחיל/גוזם ערכי צינון מול השעון.

game/ — שכבת האפליקציה

game/engine.py — class GameEngine

תפקיד: מתאם שירות־אפליקציה וגבול הפקודות הציבורי. לא בעל אף פרט: חוקיות ב־RuleEngine, תנועה ב־Arbiter, ניצחון ב־WinCondition, בחירה ב־Controller. הוא רק מרצף אותם. כל המשתפים מוזרקים בבנאי.

  • __init__(board, rule_engine, arbiter, win_condition, config, move_log, scoreboard, notation) — שמונה תלויות מוזרקות (שלושת האחרונות חדשות: יומן, ניקוד, נוטציה). עודכן
  • game_over, move_log, scoreboard, clock (properties) — ידיות קריאות־בלבד למודל־הקריאה/תצוגה.
  • is_busy(cell) — האם התא נע או קופץ כרגע.
  • can_select(cell) — האם אפשר לבחור את התא כמקור מהלך עכשיו (מסדר קודם הגעות תלויות; מסרב אחרי game-over).
  • legal_targets(cell) — התאים שהכלי יכול לזוז אליהם (לרמזי ה־UI); מאציל ל־RuleEngine ומחזיר ריק אחרי game-over. חדש
  • request_move(start, end) — הליבה: מסדר הגעות, בודק game-over/busy/resting, מאציל אימות ל־RuleEngine, ואוכף את מדיניות ALLOW_CONCURRENT_MOVES; אם הכול תקין — arbiter.start_move.
  • request_jump(cell) — בודק game-over/busy/ריק ואז arbiter.start_jump.
  • wait(dt) — מקדם זמן דרך ה־Arbiter ומחיל את האירועים שהתקבלו.
  • snapshot() — GameSnapshot קריא־בלבד (למסלול הטקסט).
  • render_model() — מודל־הקריאה העשיר לגרפיקה: כל כלי עם מצב האנימציה/דומיין שלו, השעון, יומן המהלכים והניקוד. זה מה ששרת רשת היה מסריאליזציה. עודכן
  • _render_piece(token, cell, motions) — ממפה כלי ל־RenderPiece: נע (מחליק ליעד), קופץ, במנוחה, או idle.
  • render(renderer) — מסדר הגעות ומחזיר את רינדור הטקסט של ה־snapshot.
  • _apply_events(events) — מגיב להגעות: רושם מהלך (_record_move), מזכה לכידה (_award_capture), ונותן ל־WinCondition להכריע game-over. חדש
  • _record_move(event) — בונה נוטציה דרך notation.describe ורושם ב־move_log עם השעון.
  • _award_capture(event) — צבע הכלי המגיע מזוכה בערך החומרי של הכלי הנלכד (PIECE_VALUES).

graphics/img.py — class Img

תפקיד: פרימיטיב הציור המקודש (ספרייה חיצונית ממטלת CTD26, לא שונתה). כל ציור על המסך עובר דרכה. עוטף OpenCV; שמירתה כאן מבטיחה ש־cv2 חי רק בחבילת graphics/.

  • read(path, size=None, keep_aspect=False, interpolation) — טוען תמונה ל־self.img, אופציונלית משנה גודל (מדויק, או שמירת יחס). מחזיר self לשרשור.
  • draw_on(other_img, x, y) — מצייר את התמונה על תמונה אחרת ב־(x,y), עם מיזוג אלפא לשקיפות.
  • put_text(txt, x, y, font_size, color, thickness) — כותב טקסט על התמונה (cv2.putText).
  • show() — מציג בחלון cv2 (משמש לדיבוג).

graphics/assets.py — טעינת נכסים

תפקיד: טעינת תמונות/ספרייטים (נפרד מ־Img). קורא עם np.fromfile+cv2.imdecode כי imread נכשל על נתיבים עם תווים לא־ASCII ב־Windows.

  • read_image(path, size, keep_aspect, interpolation) — טעינה בטוחת־Unicode ל־Img חדש, אופציונלית עם שינוי גודל.
  • solid(width, height, color) — Img מלא בצבע (אולי שקוף) — לשכבות־על כמו הדגשת בחירה, צעיף מנוחה, באנר.
  • _white_to_alpha(array, threshold=250) — מוסיף ערוץ אלפא לספרייט, הופך פיקסלים כמעט־לבנים לשקופים, כדי שכלים לא יופיעו בתוך ריבוע לבן.
  • _frame_paths(sprites_dir) — קבצי PNG ממוינים לפי שמם המספרי.
  • AssetLoader.load_sprite_library() — הולך על assets/pieces/<CODE>/states/<STATE>/, בונה SpriteLibrary.
  • AssetLoader._load_animation(states_dir, state) — קורא config.json (fps/loop/next state) ואת הפריימים, לגודל משבצת עם keying של הרקע הלבן.

graphics/sprite.py — SpriteAnimation

רצף פריימים על שעון. טהור וחסר־חלון: מחזיק פריימים + תזמון, ועונה "איזה פריים בזמן t".

  • __init__(frames, fps, loop, next_state) — דורש לפחות פריים אחד.
  • frame_count, loop — properties.
  • duration_ms() — זמן מעבר אחד על הפריימים.
  • is_finished(elapsed_ms) — לולאתי לעולם לא נגמר; חד־פעמי נגמר אחרי הפריים האחרון.
  • frame_at(elapsed_ms) — הפריים להצגה בזמן נתון (modulo אם לולאתי).

graphics/sprite_library.py — SpriteLibrary

חיפוש אנימציות לפי אסימון+מצב. גבול תרגום: פנימי ("wP") מול תיקיות CTD26 ("PW").

  • token_to_code(token) — "wP" → "PW".
  • animation(token, state) / has(token, state) — שליפה/בדיקת קיום אנימציה.

graphics/window.py — class Window

תפקיד: מתאם החלון+קלט של cv2. הציור לא קורה כאן — קנבס מוכן מועבר ל־show(). תצוגה וקלט יחד כי cv2 כובל אותם לחלון יחיד.

  • __init__(title, poll_delay_ms=1) — פותח חלון ורושם callback עכבר.
  • _on_mouse(event, x, y, ...) — צובר אירועי לחיצה: ("double",x,y) ללחיצה כפולה, ("left",x,y) ללחיצה. עודכן
  • show(canvas) — מציג קנבס מורכב.
  • poll_events() — מרענן וקוצר קלט; מוסיף ("quit",) על ESC/q או סגירת חלון.
  • close() — סוגר את החלון.

ui/ — לולאת המשחק והרכיבים הגרפיים

ui/game_loop.py — class GameLoop

תפקיד: מריץ את לולאת הפריימים בזמן־אמת, ותו לא. כל משתף־פעולה מוזרק ע״י שורש ההרכבה ב־play.py; המחלקה לא נוגעת ב־cv2 או בפנימיות המנוע.

  • __init__(window, engine, controller, renderer, hud, translator, base) — שבעה משתפים מוזרקים.
  • tick(dt) — פריים אחד: engine.wait(dt) → render_model → רינדור (עם selected+targets) → hud.draw → window.show → ניתוב קלט. מחזיר False על quit. שמור טהור מספיק לבדיקה עם fakes.
  • run() — בעלים רק על תזמון שעון־הקיר ועל try/finally של חיי החלון.

ui/graphics_renderer.py — class GraphicsRenderer

תפקיד: מרכיב RenderModel על הלוח דרך Img. עמית גרפי של BoardRenderer — צורך מודל־קריאה וספרייטים, לא נוגע במנוע/cv2. ממפה מצב כלי לספרייט, מחליק כלי בתנועה, ומרים קופץ בקשת.

  • __init__(sprite_library, cell_size, origin=(0,0)) — מכין שכבות־על מוכנות: הדגשה, רמז־מהלך (נקודה), רמז־לכידה (גוון), גובה קשת. עודכן
  • render(model, background, clock_ms, selected, targets) — מצייר על עותק של הרקע: הדגשת בחירה, רמזי יעדים (מתחת לכלים), הכלים, וצעיף מנוחה. עודכן
  • _draw_targets(canvas, targets, model) — רומז לכל יעד: משבצת תפוסה=גוון לכידה אדום, ריקה=נקודה ממורכזת. תפוסה נקראת מהמודל, כך שאין דליפת חוקים לתצוגה. חדש
  • _draw_rest_veil(canvas, piece) — צעיף צינון אדום שמתרוקן מלמעלה ככל ש־cooldown_progress עולה. חדש
  • _top_left(piece, frame) — פינת ציור; לכלי קופץ מרים לאורך הקשת (עם קלמפ לקצה העליון).
  • _hop_arc(progress) — הרמה אנכית: פרבולה 4p(1-p) ששיאה באמצע הקפיצה. חדש
  • _current_cell(piece) — התא (אולי שברי) לציור: היעד כשנייח, או נקודה מאונטרפולטת מהמקור בתנועה.

ui/hud.py — class Hud

תפקיד: ה"מסגרת" של הלוח — כל מה שמצויר סביבו: כותרת ("Name:"), פסי ניקוד לכל צד, תוויות a–h / 1–8, באנר game-over, ומרכיב שני MoveTablePanel (שחור משמאל, לבן מימין).

  • __init__(config) — מחשב קווי־בסיס לכותרת/ניקוד, ובונה את שני הפאנלים והבאנר.
  • draw(canvas, model) — מצייר כותרת, ניקוד, קואורדינטות, שני הפאנלים, ובאנר אם game-over.
  • _draw_title / _draw_scores / _draw_coordinates / _draw_game_over — כל אחד מצייר את חלקו. עודכן
  • _centered(text) — מעריך x למירכוז טקסט מעל הלוח (Img לא מודד טקסט).

ui/move_table_panel.py — class MoveTablePanel חדש

תפקיד: מצייר רשימת מהלכים של שחקן אחד (Time | Move) כטבלה. רכיב אחד המורכב פעמיים (שחור משמאל, לבן מימין) — כך שני הטבלאות חולקות את כל קוד הציור.

  • format_time(ms) — שעון מ״ש → mm:ss.mmm (למשל 4105 → '00:04.105').
  • __init__(title, color, x, y, width, height) — מחשב מקסימום שורות ובונה קופסה ממוסגרת מוכנה.
  • draw(canvas, model) — מצייר קופסה, כותרות, ושורות של הרשומות הנראות.
  • _visible_records(model) — בורר את הרשומות של הצבע שלו; שומר את האחרונות בגלישה.
  • _draw_headers / _draw_rows — כותרות עמודות ושורות Time/Move.

ui/input_source.py — class InputTranslator

תפקיד: מנתב אירועי חומרה גולמיים מ־Window ל־Controller. מופע אחד למקור קלט — הוספת שחקן שני = זוג (source, controller) נוסף.

  • handle(event) — "left"→controller.click, "double"→controller.jump. quit לא פקודת משחק ומושאר ללולאה. עודכן

gateway/ — התפר לרשת

gateway/gateway.py

תפקיד: חוזה בלבד (ללא לוגיקה). ה־UI תלוי ב־Protocol הזה, לעולם לא ב־GameEngine הקונקרטי — כדי שהמנוע יהיה נגיש בתהליך היום ומעל רשת מחר.

  • GameGateway(Protocol) — חמש מתודות: can_select, request_move, request_jump, wait, render_model. GameEngine כבר מקיים אותן ללא wrapper. מבוסס־הודעות/DTO: אף Board או Arbiter חי לא חוצה את התפר.
  • NetworkGateway — מימוש מרוחק מתוכנן (עדיין לא נבנה). יסריאליזציה כל פקודה ויחזיר את ה־MoveResult/RenderModel משרת שמריץ את המנוע הסמכותי. __init__ זורק NotImplementedError.
